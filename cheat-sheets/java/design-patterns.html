Creational Patterns — Object Creation
Singleton Creational

Ensure a class has only one instance and provide a global access point.

Real world: Logger, Config, Database connection pool, Thread pool

Click to see code

// Thread-safe Singleton (preferred: enum-based)
public enum AppConfig {
    INSTANCE;
    private final Properties props = new Properties();
    public String get(String key) { return props.getProperty(key); }
}

// Double-checked locking (classic approach)
public class DatabasePool {
    private static volatile DatabasePool instance;

    private DatabasePool() {}

    public static DatabasePool getInstance() {
        if (instance == null) {
            synchronized (DatabasePool.class) {
                if (instance == null) {
                    instance = new DatabasePool();
                }
            }
        }
        return instance;
    }
}

// Holder pattern (lazy, thread-safe)
public class Cache {
    private Cache() {}
    private static class Holder {
        static final Cache INSTANCE = new Cache();
    }
    public static Cache getInstance() { return Holder.INSTANCE; }
}
Use when: Exactly one object needed to coordinate actions (config, logging, connection pool). Avoid overuse — often a sign of poor design.
Factory Method Creational

Define an interface for creating objects, but let subclasses decide which class to instantiate.

Real world: JDBC DriverManager, LoggerFactory, DocumentBuilderFactory

Click to see code

// Abstract creator
public abstract class Notification {
    public void send(String message) {
        Channel channel = createChannel();  // factory method
        channel.deliver(message);
    }
    protected abstract Channel createChannel();
}

// Concrete creators
public class EmailNotification extends Notification {
    @Override
    protected Channel createChannel() {
        return new EmailChannel();
    }
}
public class SmsNotification extends Notification {
    @Override
    protected Channel createChannel() {
        return new SmsChannel();
    }
}

// Usage
Notification n = new EmailNotification();
n.send("Hello!");  // uses EmailChannel internally
Use when: A class can't anticipate the type of objects it needs to create, or you want subclasses to control object creation.
Abstract Factory Creational

Provide an interface for creating families of related objects without specifying concrete classes.

Real world: javax.xml.parsers.DocumentBuilderFactory, UI toolkit factories (Swing, AWT)

// Abstract factory
public interface UIFactory {
    Button createButton();
    Checkbox createCheckbox();
}

// Windows family
public class WindowsFactory implements UIFactory {
    public Button createButton()   { return new WindowsButton(); }
    public Checkbox createCheckbox() { return new WindowsCheckbox(); }
}

// Mac family
public class MacFactory implements UIFactory {
    public Button createButton()   { return new MacButton(); }
    public Checkbox createCheckbox() { return new MacCheckbox(); }
}

// Client uses factory - doesn't know concrete classes
public class Application {
    private final UIFactory factory;
    public Application(UIFactory factory) { this.factory = factory; }
    public void buildUI() {
        Button btn = factory.createButton();
        Checkbox cb = factory.createCheckbox();
        btn.render();
        cb.render();
    }
}

// Usage
UIFactory factory = isWindows() ? new WindowsFactory() : new MacFactory();
new Application(factory).buildUI();
Use when: System needs to be independent of how products are created, and you want to ensure families of related objects are used together.
Builder Creational

Separate the construction of a complex object from its representation.

Real world: StringBuilder, Stream.Builder, HttpClient.Builder, Lombok @Builder

Click to see code

public class HttpRequest {
    private final String url;
    private final String method;
    private final Map<String, String> headers;
    private final String body;
    private final int timeoutMs;

    private HttpRequest(Builder builder) {
        this.url = builder.url;
        this.method = builder.method;
        this.headers = Collections.unmodifiableMap(builder.headers);
        this.body = builder.body;
        this.timeoutMs = builder.timeoutMs;
    }

    public static class Builder {
        private final String url;  // required
        private String method = "GET";
        private Map<String, String> headers = new HashMap<>();
        private String body;
        private int timeoutMs = 5000;

        public Builder(String url) { this.url = url; }
        public Builder method(String m) { method = m; return this; }
        public Builder header(String k, String v) { headers.put(k,v); return this; }
        public Builder body(String b) { body = b; return this; }
        public Builder timeout(int ms) { timeoutMs = ms; return this; }
        public HttpRequest build() { return new HttpRequest(this); }
    }
}

// Usage - fluent API
var req = new HttpRequest.Builder("https://api.example.com/users")
    .method("POST")
    .header("Content-Type", "application/json")
    .body("{\"name\":\"Alice\"}")
    .timeout(3000)
    .build();
Use when: Object has many optional parameters (avoids telescoping constructors), or construction is a multi-step process.
Prototype Creational

Create new objects by copying existing ones (cloning).

Real world: Object.clone(), Spring bean prototype scope, copy constructors

Click to see code

public class ShapeConfig implements Cloneable {
    private List<String> properties = new ArrayList<>();
    private int complexity;

    // Deep clone
    @Override
    public ShapeConfig clone() {
        try {
            ShapeConfig clone = (ShapeConfig) super.clone();
            clone.properties = new ArrayList<>(this.properties); // deep copy list
            return clone;
        } catch (CloneNotSupportedException e) {
            throw new AssertionError(e);
        }
    }
}

// Better alternative: copy constructor
public class DocumentTemplate {
    private String content;
    private Map<String, String> variables;

    // Copy constructor
    public DocumentTemplate(DocumentTemplate source) {
        this.content = source.content;
        this.variables = new HashMap<>(source.variables);
    }
}

// Usage
DocumentTemplate template = loadFromFile("invoice.tmpl");
DocumentTemplate copy = new DocumentTemplate(template);
copy.setVariable("name", "Alice");  // doesn't affect original

Structural Patterns — Object Composition
Adapter Structural

Convert the interface of a class into another interface clients expect.

Real world: Arrays.asList(), InputStreamReader, Collections.enumeration()

Click to see code

// Target interface (what client expects)
public interface JsonSerializer {
    String serialize(Object obj);
}

// Adaptee (existing class with incompatible interface)
public class XmlSerializer {
    public String toXml(Object obj) { return "<obj>" + obj + "</obj>"; }
}

// Adapter wraps Adaptee, implements Target
public class XmlToJsonAdapter implements JsonSerializer {
    private final XmlSerializer xmlSerializer;

    public XmlToJsonAdapter(XmlSerializer xml) {
        this.xmlSerializer = xml;
    }

    @Override
    public String serialize(Object obj) {
        String xml = xmlSerializer.toXml(obj);
        return convertXmlToJson(xml);  // convert internally
    }
    private String convertXmlToJson(String xml) { /* ... */ return "{}"; }
}

// Client uses JsonSerializer, unaware of XmlSerializer
JsonSerializer serializer = new XmlToJsonAdapter(new XmlSerializer());
serializer.serialize(myObj);
Use when: You want to use an existing class but its interface doesn't match what you need; integrating incompatible third-party code.
Decorator Structural

Attach additional responsibilities to an object dynamically.

Real world: Java I/O streams (BufferedInputStream, GZIPOutputStream), Spring Security filters

Click to see code

public interface Coffee {
    double getCost();
    String getDescription();
}

public class SimpleCoffee implements Coffee {
    public double getCost() { return 1.00; }
    public String getDescription() { return "Coffee"; }
}

// Base decorator
public abstract class CoffeeDecorator implements Coffee {
    protected final Coffee coffee;
    public CoffeeDecorator(Coffee coffee) { this.coffee = coffee; }
}

public class MilkDecorator extends CoffeeDecorator {
    public MilkDecorator(Coffee c) { super(c); }
    public double getCost() { return coffee.getCost() + 0.25; }
    public String getDescription() { return coffee.getDescription() + ", milk"; }
}

public class VanillaDecorator extends CoffeeDecorator {
    public VanillaDecorator(Coffee c) { super(c); }
    public double getCost() { return coffee.getCost() + 0.50; }
    public String getDescription() { return coffee.getDescription() + ", vanilla"; }
}

// Stack decorators at runtime!
Coffee order = new VanillaDecorator(new MilkDecorator(new SimpleCoffee()));
System.out.println(order.getDescription()); // "Coffee, milk, vanilla"
System.out.println(order.getCost());        // 1.75
Use when: You want to add responsibilities to objects without subclassing, and extensions can be composed at runtime.
Proxy Structural

Provide a surrogate or placeholder for another object to control access.

Real world: Spring AOP, Hibernate lazy loading, Java RMI, java.lang.reflect.Proxy

Click to see code

public interface DataService {
    List<String> getData();
}

// Real implementation (expensive)
public class RealDataService implements DataService {
    public List<String> getData() {
        // expensive DB query
        return List.of("data1", "data2");
    }
}

// Caching proxy
public class CachingDataServiceProxy implements DataService {
    private final DataService real = new RealDataService();
    private List<String> cache;

    public List<String> getData() {
        if (cache == null) {
            cache = real.getData();  // call real service once
        }
        return cache;
    }
}

// Access control proxy
public class SecureDataServiceProxy implements DataService {
    private final DataService real = new RealDataService();
    private final SecurityContext context;

    public List<String> getData() {
        if (!context.hasPermission("DATA_READ"))
            throw new SecurityException("Access denied");
        return real.getData();
    }
}
Use when: Need lazy initialization, access control, logging, caching, or remote access to an object.
Facade Structural

Provide a simplified interface to a complex subsystem.

Real world: JDBC (hides socket/protocol/parsing), SLF4J (hides Log4j/Logback)

Click to see code

// Complex subsystem classes
class VideoDecoder { VideoFile decode(String path) {...} }
class AudioMixer    { AudioTrack mix(VideoFile vf) {...} }
class VideoEncoder  { byte[] encode(VideoFile vf, AudioTrack at) {...} }
class FileWriter    { void write(byte[] data, String path) {...} }

// Facade: simple API over complex subsystem
public class VideoConverter {
    private VideoDecoder decoder = new VideoDecoder();
    private AudioMixer mixer = new AudioMixer();
    private VideoEncoder encoder = new VideoEncoder();
    private FileWriter writer = new FileWriter();

    public void convert(String inputPath, String outputPath) {
        VideoFile video = decoder.decode(inputPath);
        AudioTrack audio = mixer.mix(video);
        byte[] result = encoder.encode(video, audio);
        writer.write(result, outputPath);
    }
}

// Client uses just one simple method
new VideoConverter().convert("input.mov", "output.mp4");
Use when: You want to provide a simple interface to a complex subsystem, or to layer your subsystems.
Composite Structural

Compose objects into tree structures to represent part-whole hierarchies.

Real world: File system, UI component trees (Swing, HTML DOM), XML/JSON trees

Click to see code

// Component
public interface FileSystemItem {
    String getName();
    long getSize();
    void print(String indent);
}

// Leaf
public class File implements FileSystemItem {
    private String name;
    private long size;

    public File(String name, long size) { this.name = name; this.size = size; }
    public String getName() { return name; }
    public long getSize() { return size; }
    public void print(String indent) {
        System.out.println(indent + "File: " + name + " (" + size + "B)");
    }
}

// Composite
public class Directory implements FileSystemItem {
    private String name;
    private List<FileSystemItem> children = new ArrayList<>();

    public Directory(String name) { this.name = name; }
    public void add(FileSystemItem item) { children.add(item); }
    public String getName() { return name; }
    public long getSize() { return children.stream().mapToLong(FileSystemItem::getSize).sum(); }
    public void print(String indent) {
        System.out.println(indent + "Dir: " + name + "/");
        children.forEach(c -> c.print(indent + "  "));
    }
}

// Usage - treat file and directory uniformly
Directory root = new Directory("root");
root.add(new File("readme.txt", 1024));
Directory src = new Directory("src");
src.add(new File("Main.java", 2048));
root.add(src);
root.print("");  // prints entire tree
Use when: You want clients to treat individual objects and compositions of objects uniformly (tree structure).
Bridge Structural

Separate an abstraction from its implementation so they can vary independently.

Real world: JDBC drivers, AWT peer architecture

Click to see code

// Implementation interface
public interface Renderer {
    void renderCircle(double x, double y, double radius);
}
class VectorRenderer implements Renderer {
    public void renderCircle(double x, double y, double radius) {
        System.out.println("Drawing circle as vector at (" + x + "," + y + ")");
    }
}
class RasterRenderer implements Renderer {
    public void renderCircle(double x, double y, double radius) {
        System.out.println("Drawing circle as pixels at (" + x + "," + y + ")");
    }
}

// Abstraction (bridges to implementation)
public abstract class Shape {
    protected Renderer renderer;
    public Shape(Renderer renderer) { this.renderer = renderer; }
    public abstract void draw();
}
public class Circle extends Shape {
    private double x, y, radius;
    public Circle(double x, double y, double radius, Renderer r) {
        super(r); this.x=x; this.y=y; this.radius=radius;
    }
    public void draw() { renderer.renderCircle(x, y, radius); }
}

// Choose rendering at runtime
Circle c1 = new Circle(1, 2, 5, new VectorRenderer());
Circle c2 = new Circle(1, 2, 5, new RasterRenderer());
Use when: You want to avoid permanent binding between abstraction and implementation, or both should be extensible via subclassing.
Flyweight Structural

Use sharing to efficiently support large numbers of fine-grained objects.

Real world: Integer.valueOf(-128..127), String pool, java.lang.Character cache

Click to see code

// Flyweight: shared, immutable intrinsic state
public class CharacterGlyph {
    private final char character;  // intrinsic (shared)
    private final Font font;       // intrinsic (shared)

    public CharacterGlyph(char c, Font f) { character = c; font = f; }
    // Extrinsic state (position) passed in render call
    public void render(int x, int y) { /* draw at position */ }
}

// Factory/pool manages shared flyweights
public class GlyphFactory {
    private static final Map<String, CharacterGlyph> pool = new HashMap<>();

    public static CharacterGlyph getGlyph(char c, Font f) {
        String key = c + f.getName();
        return pool.computeIfAbsent(key, k -> new CharacterGlyph(c, f));
    }
}

// Usage: 1000 'A' chars share ONE CharacterGlyph object!
for (int i = 0; i < 1000; i++) {
    CharacterGlyph g = GlyphFactory.getGlyph('A', defaultFont);
    g.render(i * 10, 100);  // extrinsic state varies, object is shared
}
Use when: An application uses a large number of objects that have mostly shared state; memory usage is a concern.
Behavioral Patterns — Object Interaction
Observer Behavioral

Define a one-to-many dependency so that when one object changes state, all dependents are notified.

Real world: java.util.Observer, Spring ApplicationEvent, Swing listeners, Reactive Streams

Click to see code

// Observer interface
public interface StockObserver {
    void onPriceChange(String symbol, double newPrice);
}

// Subject
public class StockMarket {
    private final Map<String, List<StockObserver>> observers = new HashMap<>();
    private final Map<String, Double> prices = new HashMap<>();

    public void subscribe(String symbol, StockObserver observer) {
        observers.computeIfAbsent(symbol, k -> new ArrayList<>()).add(observer);
    }
    public void unsubscribe(String symbol, StockObserver observer) {
        observers.getOrDefault(symbol, List.of()).remove(observer);
    }
    public void updatePrice(String symbol, double price) {
        prices.put(symbol, price);
        observers.getOrDefault(symbol, List.of())
                 .forEach(o -> o.onPriceChange(symbol, price));
    }
}

// Concrete observer
StockObserver alerter = (symbol, price) ->
    System.out.println("ALERT: " + symbol + " now $" + price);

StockMarket market = new StockMarket();
market.subscribe("AAPL", alerter);
market.updatePrice("AAPL", 195.5);  // alerter is called
Use when: Changes to one object require updating others, and you don't know how many objects need to change.
Strategy Behavioral

Define a family of algorithms, encapsulate each one, and make them interchangeable.

Real world: Comparator, Collections.sort(), java.util.Comparator, Spring Security authentication

Click to see code

// Strategy interface
@FunctionalInterface
public interface SortStrategy {
    void sort(int[] data);
}

// Strategies
public class QuickSort implements SortStrategy {
    public void sort(int[] data) { /* quicksort impl */ }
}
public class MergeSort implements SortStrategy {
    public void sort(int[] data) { /* mergesort impl */ }
}

// Context
public class Sorter {
    private SortStrategy strategy;

    public void setStrategy(SortStrategy strategy) {
        this.strategy = strategy;
    }
    public void sort(int[] data) {
        strategy.sort(data);
    }
}

// Usage - switch strategy at runtime
Sorter sorter = new Sorter();
int[] data = {5, 2, 8, 1, 9};

sorter.setStrategy(new QuickSort());
sorter.sort(data);  // uses quicksort

sorter.setStrategy(data.length > 1000 ? new MergeSort() : new QuickSort());
sorter.sort(data);  // auto-selects based on size

// With lambdas (Strategy is a functional interface)
sorter.setStrategy(d -> Arrays.sort(d));
Use when: You need different variants of an algorithm and want to switch between them at runtime.
Command Behavioral

Encapsulate a request as an object, enabling undo/redo, queuing, and logging.

Real world: java.lang.Runnable, Swing AbstractAction, transaction scripts

Click to see code

// Command interface
public interface Command {
    void execute();
    void undo();
}

// Concrete commands
public class MoveCommand implements Command {
    private final TextEditor editor;
    private final int deltaX, deltaY;

    public MoveCommand(TextEditor e, int dx, int dy) {
        editor = e; deltaX = dx; deltaY = dy;
    }
    public void execute() { editor.move(deltaX, deltaY); }
    public void undo()    { editor.move(-deltaX, -deltaY); }
}

// Invoker - maintains history for undo
public class CommandHistory {
    private final Deque<Command> history = new ArrayDeque<>();

    public void execute(Command cmd) {
        cmd.execute();
        history.push(cmd);
    }
    public void undo() {
        if (!history.isEmpty()) history.pop().undo();
    }
}

// Usage
var history = new CommandHistory();
history.execute(new MoveCommand(editor, 10, 5));
history.execute(new MoveCommand(editor, -3, 2));
history.undo();  // undoes last move
Use when: You need undo/redo, operation queuing, logging of operations, or transactional behavior.
Template Method Behavioral

Define the skeleton of an algorithm in a base class, deferring some steps to subclasses.

Real world: java.io.InputStream (read()), Spring's AbstractController, JUnit lifecycle

Click to see code

// Abstract class with template method
public abstract class DataProcessor {
    // Template method - defines the algorithm skeleton
    public final void process(String source) {
        String raw = readData(source);      // step 1
        String processed = parseData(raw); // step 2
        validateData(processed);           // step 3 (hook - optional)
        saveData(processed);               // step 4
    }

    protected abstract String readData(String source);
    protected abstract String parseData(String raw);
    protected abstract void saveData(String data);

    // Hook method - subclasses may override
    protected void validateData(String data) { /* default: no validation */ }
}

// Concrete implementations provide specific steps
public class CsvDataProcessor extends DataProcessor {
    protected String readData(String path) { return Files.readString(Path.of(path)); }
    protected String parseData(String csv) { return convertCsvToJson(csv); }
    protected void saveData(String json) { db.save(json); }

    @Override
    protected void validateData(String data) { JsonParser.validate(data); }
}

// Usage
new CsvDataProcessor().process("data.csv");
new XmlDataProcessor().process("data.xml");
Use when: Multiple classes share the same algorithm structure but differ in specifics; you want to avoid code duplication.
Iterator Behavioral

Provide a way to sequentially access elements of a collection without exposing its underlying representation.

Real world: java.util.Iterator, Iterable, enhanced for-each loop

Click to see code

// Custom Iterable collection
public class NumberRange implements Iterable<Integer> {
    private final int from, to, step;

    public NumberRange(int from, int to, int step) {
        this.from = from; this.to = to; this.step = step;
    }

    @Override
    public Iterator<Integer> iterator() {
        return new Iterator<Integer>() {
            private int current = from;

            public boolean hasNext() { return current <= to; }
            public Integer next() {
                if (!hasNext()) throw new NoSuchElementException();
                int val = current;
                current += step;
                return val;
            }
        };
    }
}

// Usage - works in for-each
NumberRange evens = new NumberRange(0, 10, 2);
for (int n : evens) {
    System.out.println(n); // 0, 2, 4, 6, 8, 10
}

// Also works with streams
StreamSupport.stream(evens.spliterator(), false)
    .filter(n -> n > 4)
    .forEach(System.out::println);
Use when: You want to traverse a collection without exposing its internal structure, or you need multiple traversal algorithms.

Chain of Responsibility Behavioral

Pass a request along a chain of handlers; each handler decides to process it or pass it on.

Real world: Servlet filters, Spring Security filter chain, exception handler chain

Click to see code

public abstract class RequestHandler {
    private RequestHandler next;

    public RequestHandler setNext(RequestHandler handler) {
        this.next = handler;
        return handler;
    }
    public void handle(Request request) {
        if (next != null) next.handle(request);
    }
}

public class AuthHandler extends RequestHandler {
    public void handle(Request req) {
        if (!req.hasAuthToken()) {
            System.out.println("Unauthorized");
            return;  // stop chain
        }
        super.handle(req);  // pass to next
    }
}
public class RateLimitHandler extends RequestHandler {
    public void handle(Request req) {
        if (rateLimitExceeded(req)) {
            System.out.println("Rate limit exceeded");
            return;
        }
        super.handle(req);
    }
}
public class LoggingHandler extends RequestHandler {
    public void handle(Request req) {
        System.out.println("Processing: " + req);
        super.handle(req);
    }
}

// Build chain
RequestHandler chain = new AuthHandler();
chain.setNext(new RateLimitHandler())
     .setNext(new LoggingHandler());

chain.handle(request);
Use when: More than one object may handle a request, and the handler isn't known a priori; handler set should be specified dynamically.
Mediator Behavioral

Define an object that encapsulates how a set of objects interact, promoting loose coupling.

Real world: java.util.Timer, Spring ApplicationEventPublisher, chat rooms

Click to see code

// Mediator
public interface ChatMediator {
    void sendMessage(String msg, User from);
    void addUser(User user);
}

public class ChatRoom implements ChatMediator {
    private final List<User> users = new ArrayList<>();

    public void addUser(User user) { users.add(user); }
    public void sendMessage(String msg, User from) {
        users.stream()
             .filter(u -> u != from)
             .forEach(u -> u.receive(msg, from.getName()));
    }
}

// Colleagues communicate via mediator
public class User {
    private final String name;
    private final ChatMediator mediator;

    public User(String name, ChatMediator mediator) {
        this.name = name;
        this.mediator = mediator;
        mediator.addUser(this);
    }
    public void send(String msg) { mediator.sendMessage(msg, this); }
    public void receive(String msg, String from) {
        System.out.println(name + " received from " + from + ": " + msg);
    }
    public String getName() { return name; }
}

// Usage
ChatRoom room = new ChatRoom();
User alice = new User("Alice", room);
User bob = new User("Bob", room);
alice.send("Hello!");  // Bob receives it
Use when: A set of objects communicate in complex ways, creating tight coupling; want to reuse objects independently.
Memento Behavioral

Capture an object's internal state and restore it later without violating encapsulation.

Real world: undo/redo, game save states, database transaction rollback

Click to see code

// Originator - the object whose state we save
public class TextEditor {
    private String content;

    public void type(String text) { content += text; }
    public String getContent() { return content; }

    // Create snapshot
    public Snapshot save() { return new Snapshot(content); }
    // Restore from snapshot
    public void restore(Snapshot snap) { content = snap.getContent(); }

    // Memento - snapshot of state
    public static class Snapshot {
        private final String content;
        private Snapshot(String content) { this.content = content; }
        private String getContent() { return content; }
    }
}

// Caretaker - manages snapshots
public class History {
    private final Deque<TextEditor.Snapshot> snapshots = new ArrayDeque<>();

    public void push(TextEditor.Snapshot snap) { snapshots.push(snap); }
    public TextEditor.Snapshot pop() { return snapshots.pop(); }
}

// Usage
var editor = new TextEditor();
var history = new History();

editor.type("Hello");
history.push(editor.save());  // save state

editor.type(", World!");
history.push(editor.save());  // save state

editor.type(" - some mistake");
editor.restore(history.pop()); // undo - back to "Hello, World!"
Use when: You need to snapshot and restore an object's state; direct access to state would break encapsulation.

public class Circle implements Shape {
    public double radius;
    public Circle(double r) { radius = r; }
    public void accept(ShapeVisitor v) { v.visit(this); }
}
public class Rectangle implements Shape {
    public double width, height;
    public Rectangle(double w, double h) { width=w; height=h; }
    public void accept(ShapeVisitor v) { v.visit(this); }
}

// Concrete visitor - add new operations without changing shapes!
public class AreaCalculator implements ShapeVisitor {
    private double totalArea = 0;
    public void visit(Circle c) { totalArea += Math.PI * c.radius * c.radius; }
    public void visit(Rectangle r) { totalArea += r.width * r.height; }
    public void visit(Triangle t) { /* ... */ }
    public double getTotal() { return totalArea; }
}

// Usage
List<Shape> shapes = List.of(new Circle(5), new Rectangle(3, 4));
AreaCalculator calc = new AreaCalculator();
shapes.forEach(s -> s.accept(calc));
System.out.println("Total area: " + calc.getTotal());
Use when: You need to perform many distinct operations on an object structure, and you want to avoid polluting classes with operations.
Interpreter Behavioral

Define a grammar for a language and provide an interpreter to deal with that grammar.

// Expression interface
public interface Expression {
    int interpret(Map<String, Integer> context);
}

// Terminal expressions
public class NumberExpression implements Expression {
    private final int number;
    public NumberExpression(int n) { number = n; }
    public int interpret(Map<String, Integer> ctx) { return number; }
}
public class VariableExpression implements Expression {
    private final String name;
    public VariableExpression(String name) { this.name = name; }
    public int interpret(Map<String, Integer> ctx) {
        return ctx.getOrDefault(name, 0);
    }
}

// Non-terminal expressions
public class AddExpression implements Expression {
    private final Expression left, right;
    public AddExpression(Expression l, Expression r) { left=l; right=r; }
    public int interpret(Map<String, Integer> ctx) {
        return left.interpret(ctx) + right.interpret(ctx);
    }
}

// Build expression tree for: x + 5 + y
Expression expr = new AddExpression(
    new AddExpression(new VariableExpression("x"), new NumberExpression(5)),
    new VariableExpression("y")
);

Map<String, Integer> ctx = Map.of("x", 10, "y", 3);
System.out.println(expr.interpret(ctx)); // 18
Use when: There is a grammar to interpret and efficiency is not critical; good for simple languages and expression evaluation.
