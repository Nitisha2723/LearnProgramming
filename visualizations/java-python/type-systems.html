Type Systems: Java vs Python

How each language handles types, type checking, and type safety. | Module: Java & Python Comparison

Java
Statically typed · Types checked at compile time
Python
Dynamically typed · Types checked at runtime
1. Variable Declaration
How you tell the language about a variable's type
Java: explicit Python: implicit ▼
Java
int age = 25; // must declare type String name = "Alice"; // type is mandatory double pi = 3.14; boolean active = true; // Java 10+: var for type inference var count = 10; // inferred: int
Python
age = 25 # no type declaration name = "Alice" # type inferred always pi = 3.14 active = True # Optional type hints (Python 3.5+) count: int = 10 # hint only, not enforced
Key difference: In Java, every variable must declare its type and that type is checked by the compiler. In Python, you just assign a value — the type is inferred from what you assign. Python 3.5+ added optional type hints (age: int) but these are NOT enforced at runtime — they're just documentation.
2. Type Checking — When Do Errors Happen?
Static vs dynamic type checking
Java: compile-time Python: runtime ▼
Java — Compile Error (safe!)
String s = "Hello"; int n = 5; String result = s + n; // "Hello5" OK! // This FAILS to compile: int x = "not a number"; // ERROR: incompatible types // String cannot be int // Caught BEFORE running!
Python — Runtime Error (discovered later)
s = "Hello" n = 5 # This runs fine: result = s + str(n) # "Hello5" # This FAILS at runtime: result = s + n # TypeError: can only concatenate # str (not "int") to str # Only caught WHEN executed!

Type operation outcomes:

"str" + 5
Java: COMPILE ERROR — caught before running Python: TypeError at runtime
"str" + "5"
Java: "str5" (string concat) Python: "str5" (string concat)
1 + True
Java: COMPILE ERROR — int + boolean disallowed Python: 2 (True == 1, allowed!)
Static typing (Java): The compiler knows the type of every expression and rejects wrong-type operations before the program runs. You catch errors earlier — great for large teams and refactoring.

Dynamic typing (Python): Types are checked when the code actually executes. A bug in an untested code path could live silently until production. But it's faster to write — no declarations, very flexible.
3. Type Casting & Conversion
Converting a value from one type to another
Java: explicit cast Python: constructor ▼
Java
// Widening (automatic): int i = 42; long l = i; // int → long, safe double d = i; // int → double // Narrowing (explicit cast needed): double pi = 3.14; int n = (int) pi; // truncates: n=3 // String conversion: int x = Integer.parseInt("42"); String s = String.valueOf(42);
Python
# Implicit widening in expressions: i = 42 f = i / 3 # int/int → float (14.0) f2 = i + 0.5 # int + float → float # Explicit conversion with constructors: pi = 3.14 n = int(pi) # truncates: n=3 # String conversion: x = int("42") # str → int s = str(42) # int → str
Java: Widening conversions (small → larger type) happen automatically. Narrowing (large → smaller, potentially losing data) requires an explicit cast like (int). This makes data loss intentional and visible.

Python: Uses constructor functions (int(), float(), str()) for explicit conversion. Division of two ints always gives a float in Python 3 (unlike Java where 5/2 = 2).
4. Type Inference — Letting the Compiler/Interpreter Figure It Out
When you don't have to write the type explicitly
Java 10+: var Python: always ▼
Java 10+ — Local Variable Type Inference
// Before Java 10 (verbose): ArrayList<String> list = new ArrayList<String>(); // Java 10+: var infers the type var list2 = new ArrayList<String>(); var x = 42; // inferred: int var name = "Bob"; // inferred: String // BUT: type is FIXED at compile time x = "hello"; // COMPILE ERROR! // x is still int, just inferred
Python — Always Inferred, Always Dynamic
# Python always infers type list2 = [] # type: list x = 42 # type: int name = "Bob" # type: str # AND: you can REASSIGN to different type x = "hello" # now x is str! x = 3.14 # now x is float! x = [1, 2, 3] # now x is list! # All valid in Python
Java's var: Reduces boilerplate but still statically typed — the inferred type is fixed at compile time. You can't reassign to a different type later.

Python: All variables are always dynamically typed. A variable is just a name pointing to an object — you can point it to ANY object at any time. This is maximally flexible but can lead to surprising bugs.
