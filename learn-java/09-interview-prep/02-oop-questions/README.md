# OOP and Design Patterns Interview Questions

This module contains 30 interview questions covering Object-Oriented Programming principles, SOLID design principles, and common design patterns. These questions are frequently asked in mid-level to senior Java developer interviews.

## Topics Covered

### 1. Four Pillars of OOP (Q1-Q4)
- Encapsulation, Inheritance, Polymorphism, Abstraction
- Java-specific examples and trade-offs

### 2. SOLID Principles (Q5-Q9)
- S: Single Responsibility Principle
- O: Open/Closed Principle
- L: Liskov Substitution Principle
- I: Interface Segregation Principle
- D: Dependency Inversion Principle

### 3. Design Fundamentals (Q10-Q11)
- Coupling vs cohesion
- Why design patterns exist

### 4. Creational Patterns (Q12, Q13, Q16, Q20)
- Singleton (thread-safety variants)
- Factory Method
- Builder
- Abstract Factory

### 5. Behavioral Patterns (Q14, Q15, Q27, Q28)
- Strategy, Observer, Template Method, Chain of Responsibility

### 6. Structural Patterns (Q17, Q18)
- Decorator, Repository

### 7. Dependency Injection (Q19)
- Constructor, setter, and interface injection

### 8. OOP System Design (Q21, Q22)
- Parking lot and library system design

### 9. Advanced OOP Concepts (Q23-Q30)
- Interface vs abstract class for design
- Method hiding vs overriding
- Covariant return types
- Multiple inheritance via interfaces

## How to Study

**Step 1: Master the Four Pillars First.** If you cannot explain encapsulation, inheritance, polymorphism, and abstraction with code examples, start here.

**Step 2: Learn SOLID with Violations.** For each SOLID principle, study both a violation and the refactored version.

**Step 3: Implement Each Design Pattern.** Write each pattern from scratch in your IDE: Singleton, Observer, Strategy, Builder.

**Step 4: Practice System Design.** For Q21 and Q22, draw class diagrams before reading the answers. Compare your design to find what you missed.

**Step 5: Connect SOLID to Patterns.** Factory implements Dependency Inversion. Strategy implements Open/Closed. Observer implements Single Responsibility.

**Step 6: Practice Explaining Trade-offs.** For every design choice, practice saying "I chose X over Y because..." and "The downside of this is..."
